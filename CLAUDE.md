# Notes for Claude

- Godot 4.6.2, GDScript, Forward+ renderer. PC only.
- The owner tests in the Godot editor; Claude can't see the game. Validate changes headless before pushing:
  `godot --headless --path . --import` then run a smoke-test `SceneTree` script.
- Prefer generating complex `.tscn` files with a headless build script over hand-writing them.
- Typed GDScript (`:=`, typed params), tabs for indentation, `class_name` on reusable scripts.
- Physics layers: 1 world, 2 players, 3 enemies.
- Character rig: Mixamo (`mixamorig:` bones), shared by masc and femme bodies. Femme body parts are prefixed `f_`.
- `HANDOFF.md` (repo root) has the current to-do list and agreements: read it first in a new chat.
- Design doc lives as a Claude doc ("Titamas Online — Design Doc"); README has Blender and level-chunk conventions.
- Visual checks: `xvfb-run -a godot --path . --rendering-driver opengl3 --script <shot.gd>` renders screenshots (software GL).
- Bodies: `assets/models/characters/base_bodies.scn` (built by `tools/godot/build_bodies.gd`). Masc = the user's low-poly Blender body (`src/lowpoly_guy.glb`, Mixamo rig, A-pose, middle finger instead of ring), baked to metres facing -Z, 1.86 m, parts head/torso/arms/hands/legs/feet + textured `underwear`; femme is the old body copied from `base_bodies.glb`, unused: the owner uses the masc body for every character (no femme version planned). The same script saves the glb's other meshes as fitted scenes in `assets/characters/lowpoly/` (PIECES: outfit pieces split by material/height, head_elf, face_default, hair_short/balding, tin_hat). Appearance lists `heads` (elf hides `head`) and `faces` (`painted` = textured face mesh, skips eye quads). What gets built is `data/body_models.json` (Database tab Body Models: source glb, height, body meshes, body_extra materials→parts, pieces {id, mesh, material, min_y, max_y, bone}; the plugin lists the glb's meshes via `_glb_meshes()` and `/api/rebuild_bodies` runs build_bodies + make_appearance in a thread). After a new export: Rebuild there (or build_bodies → make_appearance), retarget_mixamo if the rig changed, refit_rigid + `tools/godot/apply_refit.py` if proportions changed.
- When building scenes by script, never set `owner` on nodes inside an instanced scene (causes duplicate-node load errors).
- Animations: Mixamo FBX (Without Skin) go in `assets/animations/mixamo/`; run `godot --headless --path . --script res://tools/godot/retarget_mixamo.gd` (or Database → Animations → Rebuild: plugin `/api/rebuild_animations` runs it in a thread) to rebuild `masc.res`/`femme.res`. Per-clip settings (loop, in_place, root_motion, no_hip_rise, yaw_fix, height_match, kind file/cut/reversed + from/start/end) live in `data/animations.json` "clips" (Database tab Clips); the tool's LOOPING/ROOT_MOTION/SUBCLIPS... vars are filled from it. `roles` there map what the game asks for ("running", "hanging_idle", "death", "talk_1"...) to clips: `CharacterModel.roles` (static, set by Database) → `clip_for()` in play/play_from/measure/root motion/has/length; `current_animation()` returns the role. Also `look` (HeadLook defaults, NPC look range) and `strafe` speeds. Always add new tunables to the data files + Database page. Facing is derived from hip anatomy, not bone axes.
- `PlayerAnimator` picks animations from movement; `CharacterModel.play()/play_from()` crossfade. Animations only run in-game (not in the editor) so bone poses never get saved into scenes.
- Player states (PlayerController.State): NORMAL, DODGE, HANG, LEDGE_CLIMB, WALL_CLIMB, LADDER, SWIM. Surfaces are marked (`PlayerController._marked(node, kind)`, node or 3 parents): ledges by group `grabbable`/`climbable` or name containing `_grab`/`_shimmy`/`_climb` (unless player.json movement `grab_any_ledge`; climbing out of water takes any edge), walls by `climbable`/`_climb`, ladders by `ladder`/`_ladder`. Stuck airborne on steep geometry (`_stuck_air`) → jump pushes off; `WaterVolume` (physics layer 4) marks water. One-shot moves emit `action_animation`; continuous states call `character.play()` directly.
- Converter extras: `ROOT_MOTION` (travel baked to metadata), `YAW_FIX` (clips facing backwards), `HEIGHT_MATCH`, `ARM_SPREAD`.
- World: `Ocean` (group "ocean", sea level −5 m) follows the player; `_water_at()` treats anything below sea level as water. Fatigue builds when swimming >48 m from the nearest chunk; kill floor at −80 m; both respawn at the last dry ground. `AtmosphereManager` blends `RegionAtmosphere`s (built from data/regions.json, chunk rectangles) and shows the zone name.
- Chunk materials are swapped by name for `assets/materials/terrain/<name>.tres`; chunk meshes named `*-water` become water (shader + swimmable `WaterVolume`).
- Props: `chunk_I_J.props.json` beside each chunk lists {name, pos, basis columns} in chunk space; `PropLibrary` loads `assets/props/<name>.glb`, applies `foliage_wind.gdshader` to foliage names and adds collision (tree trunk cylinder / convex hull / none). JSON files must be included when exporting the game (Export → Resources → filters: `*.json`).
- Sound: buses Master/Music/SFX/Ambience (`default_bus_layout.tres`). `PlayerAudio` (under Player) times footsteps/strokes/grabs from `CharacterModel.bone_contacts()` and picks the surface from `ChunkStreamer.paint_at()` (terrain UV2 paint), slope, `surface` metadata (props get it from `PropLibrary.surface_of`), group `ladder`, water. Region ambience + altitude wind in `AtmosphereManager`, surf in `Ocean`. Generated sounds: `tools/audio/make_ambience.py` (numpy + ffmpeg). Credits in `assets/audio/CREDITS.md`. Headless quit() while loops play prints a harmless "resources still in use" leak warning.
- Combat: anything fighting is in group `combatants` with a `Stats` child (display_name, level, team PLAYERS/ENEMIES, `immortal`, heal-over-time). `Combat` (static) finds enemies, scales damage by level, applies hits (target may implement `modify_incoming_damage` / `stagger`), plays sounds, spawns numbers. `Ability` objects from `data/abilities.json` (MELEE / PROJECTILE / HEAL_OVER_TIME) are run by `PlayerCombat`; `Targeting` handles Tab/click/auto-target. PlayerController has states ACTION (attacks/casts/block; dodge cancels via `action_interrupted`) and DEAD. Enemies: `Enemy` (CharacterBody3D, layer 3, AI IDLE/CHASE/ATTACK/STAGGER/RETURN/DEAD) and `TrainingDummy`; `Nameplate` over them. Placeholder combat clips come from `PLACEHOLDERS` in `retarget_mixamo.gd` (an FBX of the same name overrides). Weapons are stand-in meshes from `WeaponModels`, held via `CharacterModel.attach_to_hand()` (grip worked out from finger bones; bodies have thumb/index/ring only) and sheathed on the back via `attach_to_bone()` outside combat. Test with `InputEventAction` through `Input.parse_input_event` for "attack" (it's read in `_unhandled_input`).
- Controls (Fable style, see design doc): one `attack` action, meaning set by the one weapon in hand (`PlayerCombat.weapon`/`weapon_type`, equipment slot "primary"; no secondary any more: old saves' second weapon goes to the bag and onto hotbar 1/2, `Inventory.RETIRED_SLOTS`). Weapons on the hotbar ("item:<weapon>") are taken in hand by `PlayerCombat.switch_to_weapon`; `cycle_mode` is only Take all in loot; tap < `tap_time` = quick, hold = charge (heavy / bow draw; `Ability.charge_time/charge_power`). Crossbows/guns fire on press then reload (`_unloaded`, `_reload_left`). `block` = block (melee) or aim (ranged: `_set_aiming`, camera `set_aiming`, `aim_point`/`aim_on_enemy`, `crosshair()`). `hotbar_1..10` → `use_hotbar(i - 1)` (Inventory.hotbar, HOTBAR_SIZE 10, entries "ability:id"/"item:id"; spells cast-only via `cast()`; gold frame on the box whose weapon is in hand), `ability_wheel` (hold D-pad up, right stick picks; sets `GameSettings.wheel_open` so the camera ignores the stick, movement stays), `spellbook` (P), `chat` (Enter). `target_next` = target+lock / clear (`Targeting.toggle_target` → `best_in_view()`: screen-centre distance + range; lock_range ≥ tab_range so a fresh lock never breaks at once), `target_prev`/Shift+Tab cycle, `lock_on`; melee swings snap to enemies within `Targeting.snap_range`. HUD polls `PlayerCombat.bar_state()` for the cast/charge/reload bar. Stamina = sprint only. Input map has keyboard/mouse and joypad events (device -1).
- Weapons: `data/weapon_types.json` (Database `weapon_type(id)`, tab "Weapon Types": category melee/ranged, hands, combo/heavy/shot ability ids, speed, power, draw, reload, swap/fire sounds). Weapon items have `slot: "weapon"`, `weapon_type`, `speed`, `auto_aim` (default true; crosshair only when false); `Inventory.fits/target_slot/equip_from(index, slot)`; old saves' main_hand/ranged map to primary/secondary. Classes list `proficient` types (`PlayerCombat.is_proficient`, `dps_of(item)` for tooltips). Projectile styles BOLT (homing spells) / ARROW (gravity when hand-aimed, sticks via `_stick`) / BULLET (straight, `_bullet_hole` Decals); `Projectile.launch(..., dir, gravity)`, `Projectile.ballistic()`. Builtin weapon models in `WeaponModels` (dagger, greatsword, hammer, axe, crossbow, pistol, rifle; grip at origin, blade +Y). Sounds from `tools/audio/make_weapon_sounds.py`. `LootChest` (scenes/world/loot_chest.tscn, talkable, once per character via `GameSession.data.opened_chests`).
